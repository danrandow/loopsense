# GTM retro — iteration 0

- **What worked:** The write-boundary + session-protocol split in `SKILL.md` meant I never had to guess what I was allowed to touch — the explicit file list up front removed a whole class of "can I edit this?" hesitation. Standing rule 1 (ignore `context.md`) also headed off a conflict before it happened: the project instructions actively pointed me at a file I'm told to ignore, and having that resolved in writing meant no wasted cycle chasing an unreachable path.
- **What didn't:** The log-append discipline (rule 6) is solid in principle but fragile in practice under concurrent writers — my first append failed because another agent (exec) had appended id 123 between when I read the tail and when I wrote, so my computed id and old_string were both stale. It's a one-retry fix, not a real blocker, but it's a guessable collision point once more than one agent is closing out the same iteration on the same day.
- **One change:** Give the log an atomic append primitive (or a short id-reservation step) instead of read-tail-then-string-replace, so same-day multi-agent writes don't need a compute-and-hope retry loop. Short of that, a convention where each agent's log entry carries a self-describing anchor (e.g. always match on the closing `]` plus a regex for "last id" rather than a hand-copied literal block) would make the retry cheaper when it does happen.
