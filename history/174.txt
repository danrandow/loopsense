Reusable OpenClaw retrospective workflow

WHY:

Dan should be able to initiate a full LoopSense retrospective with the natural instruction “Loopy, run the retro” rather than restating the delegation, logging, synthesis and Git procedure every iteration. The Railway runtime is also becoming a writer, so the workflow needs an explicit clean-repository boundary and safe synchronization behavior.

SCOPE:

- openclaw/workflows/retro.md
- openclaw/agents/loopy/AGENTS.md
- openclaw/README.md

BEFORE:

The retrospective procedure was distributed across iteration-0-specific prompts, working context, standing rules and chat instructions. Loopy could delegate to the four configured agents, but no durable OpenClaw workflow defined the short trigger or safe Git lifecycle.

AFTER:

“Loopy, run the retro” invokes one repository-owned workflow. Loopy identifies the current iteration, records unfinished experiments honestly, synchronizes only from a clean starting tree, delegates sequentially to PM, Exec, Delivery and GTM, verifies their own retro files, writes a cross-agent synthesis, and commits and pushes the exact retro outputs without force or automatic harness edits.
