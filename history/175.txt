Reusable OpenClaw next-iteration workflow

WHY:

Dan should be able to start a LoopSense iteration with a natural instruction while preserving his control over the product direction and over changes proposed by the retrospective. The four role agents should then run in sequence without Dan manually starting each one.

The workflow needs an explicit decision checkpoint because Loopy's canonical boundary requires Dan to approve specific changes to skills, rules, YAML, knowledge files and other agents' files. Retro recommendations are proposals, not automatic authority.

SCOPE:

- openclaw/workflows/start-next-iteration.md
- openclaw/agents/loopy/AGENTS.md
- openclaw/README.md

BEFORE:

The repository defined a reusable retro workflow, but starting an iteration still required Dan to restate direction, approve improvements separately and manually trigger PM, Exec, Delivery and GTM.

AFTER:

“Loopy, start the next iteration” begins a two-phase workflow. Loopy reads the latest retro and Dan's optional direction, proposes exact improvements and the iteration objective, and pauses for approval. After approval it applies only those changes, creates the next iteration skeleton, and orchestrates PM, Exec, Delivery and GTM sequentially with validation, bounded commits, normal pushes and safe stops on returns or conflicts.
