OpenClaw adapters for PM, Exec, Delivery and GTM

WHY:

LoopSense needs all five existing roles available as distinct agents in the always-on OpenClaw runtime. Their identity and bootstrap files are part of the product and must remain versioned with the canonical role instructions. OpenClaw credentials, sessions, databases and other runtime state remain outside Git.

The adapters are deliberately thin. They load each role's existing canonical SKILL.md and project instructions, preserve the existing strict write boundaries and handoff sequence, and add only runtime-facing safeguards against stale-state reporting, accidental cross-role writes and unapproved external actions.

SCOPE:

- openclaw/README.md
- openclaw/agents/pm/{AGENTS,SOUL,IDENTITY,USER}.md
- openclaw/agents/exec/{AGENTS,SOUL,IDENTITY,USER}.md
- openclaw/agents/delivery/{AGENTS,SOUL,IDENTITY,USER}.md
- openclaw/agents/gtm/{AGENTS,SOUL,IDENTITY,USER}.md

BEFORE:

Only the Loopy OpenClaw adapter existed.

AFTER:

All five LoopSense roles have repository-owned OpenClaw adapter workspaces. The README lists the workspace paths and repeats the product/runtime boundary.
